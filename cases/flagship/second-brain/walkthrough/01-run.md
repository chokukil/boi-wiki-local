# 비개발자 실행 Walkthrough

대상: Git·Python·Obsidian을 모르는 구성원

예상 시간: 첫 설정 10분, 첫 지식 5분

선행 조건: Codex 또는 Claude 같은 파일 작업 가능한 AI와 이 저장소 폴더. Obsidian·MCP는 선택입니다.

## 1. AI에게 한 문장 전달

~~~text
이 저장소를 내 Local Private Second Brain으로 설정하고, 오래 쓸 가치가 있는 대화와 지정 폴더 자료를 기존 지식에 반영해줘. 원본과 이력은 보존하고 원격 업로드는 하지 마.
~~~

정상 결과: AI가 최대 3개만 묻습니다—Local Profile ID, 자동 정리 수준, 선택 자료 폴더.

문제가 생기면: Python 설치나 터미널 명령을 요구하는 경우 작업을 멈추고 “일반 사용자 경로로 다시 설정해줘”라고 말합니다.

## 2. 쉬운 설정 요약 승인

AI가 다음을 5줄 안팎으로 설명해야 합니다.

- 대화 관리 방식
- 자료 폴더
- 원본 보존 켜짐
- 원격 자동 업로드 꺼짐
- Obsidian/MCP 없이 사용 가능

정상 결과: 승인 전에는 Local Profile을 만들거나 기존 설정을 바꾸지 않습니다.

## 3. 첫 지식 만들기

~~~text
오늘 결정한 내용 중 한 달 뒤에도 쓸 것만 기존 지식과 비교해 반영해줘. 일회성 일정이나 잡담은 저장하지 마.
~~~

정상 결과: AI가 기존 topic을 먼저 검색하고, 보강·교정·신규·확인 필요 중 하나를 선택합니다. raw chat 전체를 파일로 복사하지 않습니다.

## 4. 자료 폴더 정리

이메일 저장 파일, 웹 clip, CSV, PDF, 이미지, 회의 메모를 지정 폴더에 둔 뒤 말합니다.

~~~text
자료 폴더를 원본 그대로 두고 기존 Second Brain과 비교해 정리해줘. 중복은 만들지 말고 확인이 필요한 것은 따로 알려줘.
~~~

처음에는 파일을 만들지 않고 대상 파일 수, 중복, 정리 묶음, 기존 지식과의 관계, 원본 보존과 원격 업로드 꺼짐만 보여줍니다. 범위가 맞으면 다음처럼 한 번 승인합니다.

~~~text
이 미리보기의 자료와 범위대로 정리해줘.
~~~

정상 결과:

- 기존 지식 보강
- 새 주제
- 이미 반영됨
- 확인 필요
- 남은 자료

수량을 묶어서 보여줍니다. 파일별 승인을 반복해서 묻거나 schema 설명을 먼저 보여주지 않습니다.

## 5. 중단됐던 자료 정리 이어가기

AI 세션이 끝나거나 자료가 많아 일부만 처리됐다면 다음처럼 요청합니다.

~~~text
승인했던 자료 폴더 정리를 중단된 지점부터 이어서 해줘. 이미 반영한 파일은 다시 만들지 마.
~~~

정상 결과: AI가 승인 당시의 계획과 현재 파일 SHA256을 먼저 대조합니다. 파일과 범위가 그대로면 추가 승인 없이 다음 묶음부터 이어가고, 파일이 바뀌었거나 계획이 맞지 않으면 쓰기 전에 새 미리보기를 보여줍니다. 완료된 자료를 다시 처리하거나 기존 지식을 복제하지 않습니다.

## 6. 질문하고 재사용

~~~text
이 결정이 왜 내려졌는지 출처, 반증, 아직 모르는 것, 다음 확인과 함께 알려줘.
~~~

정상 결과: 근거 문서를 다시 열 수 있는 링크, confidence, 반증과 근거 부족 표시가 있습니다. Local 출처의 SHA256은 검증 세부 정보에서 확인할 수 있으며, 답이 부족하면 AI가 모른다고 말합니다.

## 7. 잘못된 기억 교정

~~~text
이 기억은 틀렸어. 이전 내용과 근거는 보존하고, 이 자료를 기준으로 최신 내용으로 교체해줘.
~~~

정상 결과: 이전 문서를 삭제하지 않고 교정 관계와 source를 남깁니다. 상충 근거가 있으면 자동 확정하지 않습니다.

## 8. 조직지식 후보 만들기

~~~text
이 내용 중 팀이 재사용할 방법만 일반 knowledge로 정제해서 Team promotion preview를 보여줘. 제출은 하지 마.
~~~

정상 결과: reviewer, Team 범위, 공유 가능한 출처와 “아직 제출되지 않음”이 먼저 보입니다. exact candidate hash와 `user_confirmed: false`, `remote_submit_allowed: false`는 검증 세부 정보에 남습니다.

## Local/Remote 경계

- MCP 없음: Local 문서만 작성·검색·정리
- MCP 연결: ACL이 허용한 사내 BoI를 읽고 Local 작성에 인용 가능
- MCP 연결만으로 Local Private 자동 업로드 없음
- Team/Public: 정제 → 검사 → preview → 사용자 승인 → 지원되는 원격 기능 순서
